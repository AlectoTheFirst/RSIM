# UI

`ui/` is the browser UI: TypeScript with Preact, built with Vite, with exact versions in `ui/package.json` and the committed lockfile. `ui/src/theme.ts` holds the colour, type and size tokens of `../rsim-project/design/ui-design-language.md` and sets them as CSS custom properties; each CSS file of `ui/src` uses only these properties and the properties that a TSX style sets, which `ui/test/css.test.ts` checks, and each view has its own CSS file, which `ui/src/main.tsx` loads.

Each page has the frame of `App.tsx`: the navigation rail (`page/Rail.tsx`) with the wordmark `RSIM`, the views Trace, Topology, Tables and Coverage, and Inventory at the bottom; the top bar (`page/TopBar.tsx`) with the snapshot selector, whose options are the held and the previous snapshot of the store (`runOptions` of `page/frame.ts`) and each other twin, the time of the run and the pill `newest` or `older`, the button "Load newest snapshot", the age of the last cycle, the menu Preferences (theme, colours, row height) and the account menu ("My API tokens", "Sign out"); and the content, cards on the page ground, below a page head with the tabs or the controls and the actions of the page when the page has them; no page prints its name.

`ui/src/page/` holds the shared parts: `Card.tsx` (`Card`, `PageHead`, `PanelLayout` and `Empty`, the state of a card with no content), `Panel.tsx`, `Tabs.tsx`, `Pill.tsx` (`Pill` and the filter `Chip`), `Segmented.tsx`, `Menu.tsx`, `Icon.tsx`, `Hatch.tsx`, `Parts.tsx` (the query card and `PageButtons`) and the toast (`notes.ts`, `Toast.tsx`), which shows the note of the last action for 4 s. A selection opens a panel at the right of its table or drawing, 352px wide, and the table does not move; Escape closes the panel and the focus goes back to the control that opened it. Each list draws only the rows in view through `page/VirtualRows.tsx` and its model `page/virtual.ts`: the rows of a table, the devices of the inventory, the paths of a query, the parts of a set query, the options of a picker and each list of a panel, with the row height of the preferences. A picker reads 50 options for each page (`PICKER_MAX` of `page/pick.ts`) and reads the next page when its list shows its last row.

The view Trace (`ladder/Trace.tsx`) has the query card, the outcome card, the card Paths of a query with more than one path or the card Parts of a set query, the ladder card of the selected path or part, and the step panel (`ladder/StepPanel.tsx`).

`ui/src/page/fields.ts` gives the fields of the query card: their order, the description and the names of each field from `ui/src/api/fields.ts`, the one form of the values of each field, where a comma separates the values of a list and `+` joins the TCP flags of one packet, the check of the form with the rules of the argument parser of the server, and the query type of the values (`queryMode`): a set query when a stated field has a prefix, a list or a range, else a path query; each field is an input below its name, a base field with no value shows the hatch and "not stated", the card has the buttons "Swap source and destination", "Add field" and "Run", and a value with a wrong form stops the run and shows its message below its field.

The outcome card gives the outcome, the reply, the path strip of the selected path with the site of each device from the inventory and, for more than one path, the outcome over all paths and one button for each outcome that occurs with the number of its paths, which filters the card Paths. `ui/src/ladder/paths.ts` gives the rows of the card Paths, one for each path and each copy of a flood in the order of the answer, the outcome counts and the path strip; path 1 is selected.

`ui/src/ladder/layout.ts` gives the lanes, the rows and the cells of the ladder of one path, and of one part of a set query, from the full form of an answer: one lane for each device of the selected path, the columns step, lanes, function, reason, rewrite and source lines, and a function column as wide as the longest function name of the answer from 168px to 264px, where a name wraps after a `/`, else at a space. `ui/src/ladder/setLayout.ts` gives the list of the parts of a set query: for each branch the header fields in which its packets differ from the packets of the query, its outcome and the tunnel of an outer packet that exits or is delivered; both have no drawing code.

The step panel has the step, "Previous step", "Next step", the reason, the rewrite, the source lines with a mark on the most specific span, the parameters, the QoS values, the RIB guard, "Copy as rsim explain" and "Copy step URL". The drawings are SVG rectangles, lines, circles and text, and the hatch is SVG lines in a clip path.

The view Topology (`?view=topology`, `ui/src/topology/`) draws one scope of the twin from `GET /v1/twins/{twin}/topology` with the parameters `device`, `around` and `hops`: a site of the inventory, the paths of a query with the neighbours of their devices, one device with its neighbours, else the whole twin (`scope.ts`); the scopes of the paths and of a device add the neighbours of each device of the URL parameter `expand`, and a scope of more than 300 devices (`MAX_DRAWN`) does not draw and shows the field Device. The views Trace and Topology share no parameter: the button "Show in topology" of the outcome card opens the Topology view with the query (`topologySearch` of `url.ts`), and each other link to the Topology view has no query. The page head has a chip for the query, the device, the site and each expanded device, each with a remove button. The fields Site and Device show 50 options for each page of the sites of the inventory or the devices of the twin that start with their text.

The layer overlay draws the physical links in the colour `rule` below the tunnels. A node of the kind `network` is a card of a device of the twin with round ends. The overlay layer of the API has the VXLAN tunnels and a tunnel from each WireGuard interface to each peer: the device whose WireGuard source address is the endpoint of the peer, else a node `peer` outside the twin, which the map draws as a hatched card; the path drawing of a query ends a WireGuard tunnel with no decapsulation at that peer, and the map draws the exit of the path as a dashed link from its port to the peer card. A VCMP tunnel of the overlay layer goes from the device of its `VcmpEncap` to the device whose WAN link has the peer address, as the source of a `VcmpEncap` or a local host route of a route lookup before a `VcmpDecap` (`topology::vcmp_ends`), else to a node `peer`; its tunnel facts have the WAN interface, the segments and the state of the tunnel in `OverlaySelect`.

`graph.ts` reads the answer into cards and lines, one line for the links between 2 devices with their number when there is more than one, `layout.ts` gives the ranks, the rows of at most 32 cards and the lines of horizontal and vertical segments, `view.ts` the zoom, the pan and the cards and lines inside the window, `paths.ts` the paths of the query from the brief form `steps` and the tunnel peers from the path drawing, `select.ts` the lines and the facts of the selected device and `draw.ts` the labels; all have no drawing code. The device panel has the facts of the table `devices`, the links, the endpoints, "Show neighbours" in the scopes of the paths and of a device, "View functions" and "Use as entry point", and "Export" saves the GraphML, Mermaid or D2 form.

The view Tables (`ui/src/tables/`) has the table list with a search field, the table card with the forms of the table as tabs, a chip for each filter, "Add filter", the menu of each column head (sort, filter, hide; the URL parameter `hide` holds the hidden columns) and the rows of `Table.tsx`, and the row panel (`RowPanel.tsx`) with each value of the row, the source lines of its spans and the actions of the row; the row panel of the table `devices` has the button "View functions", which opens the table `functions` filtered to the device.

The view Coverage (`ui/src/coverage/`) has the table card of the devices and the unhandled paths of the selected device in the panel.

`crates/rsim-api/build.rs` sets the cfg `rsim_ui` when `ui/dist` holds the built files, and `crates/rsim-api/src/ui.rs` embeds them by their fixed names. The server serves them at `/`, `/assets/` and `/fonts/` with a content security policy, and accepts the origin of its own address.

The view Inventory (`?view=inventory`, `ui/src/inventory/`) has the tabs Devices, Credentials, Routes and Collection. It reads `/v1/inventory`, `/v1/inventory/devices` and `/v1/inventory/vendors`, and the table `neighbours` of the twin of the top bar; the time of the last cycle and the serial of a device come from the table `devices`, read only for the device rows in view, where a store device with no row of its own, such as a UniFi console, takes the newest time of the rows of its manifest.

`ui/src/inventory/model.ts` gives the arrangement by device group, site or credential, the filter by device, address and site, the fold of a group, the columns SSH and trust (the TLS trust of a group collected over HTTPS, and the hatch "not known" for a group collected over SSH), the state of each setting cell (a hairline for a value from the group row, the `parameter` colour for a value of the device, a hatch for none), the age of the last cycle, the hops of the routes and the write bodies, each the stored record of `GET /v1/inventory` with only the edited fields changed. A click or Enter on a group row folds its devices, and its button "Edit" opens the group panel; a click or Enter on a device row opens the device panel.

The panel of a device or a group (`Records.tsx`, `SettingsEditor.tsx` with `SETTING_FIELDS` of `model.ts`) edits each field of the record and each setting with its origin as a pill: a change edits the draft, "Save" or Enter in a field writes the draft in one PUT, Escape in a field reverts that field, "Cancel" drops the draft, an empty setting inherits, a number is checked against the range of the database before the write, and a setting that the transport, the vendor or the collector does not use is not shown; "Delete <name>" asks one time and removes the record on the second press. "Add device" and "Add group" open the panel of a new record. The card "Neighbours" lists each LLDP or CDP neighbour with no inventory record, and its button "Add to a group" opens the panel of a new device with the name.

In the tabs Credentials, Routes (with the card Jump hosts) and Collection, an add row or an edit commits on Enter or on a second press of its button, Escape cancels, and the Delete button of a record removes it on a second press. The tab Collection edits `history_days` ("history", the unit "days" after the input), checked by `collectionChecked` of `model.ts` before the write. The tab Credentials gives the source `managed` with the kind, the user and a secret field, a text area for a private key, only when `GET /v1/inventory/secret-key` gives a key; an empty secret field keeps the stored secret, and `credentialBody` of `model.ts` gives the PUT body. A refused write, and a new record whose name is in use, shows the title of its problem in the toast. With no inventory database, the view shows the mark `no inventory database`.

`ui/src/auth/` holds the sign-in of the page: `Gate.tsx` reads `/v1/auth/setup` and shows the one-time setup page while no user exists, else the sign-in page until `/v1/auth/me` answers, each a card on the page ground with no frame, and else the views; with no sign-in on the server the page has no account menu. Each request goes through `send` in `ui/src/api/client.ts` with the session cookie, and a 401 returns to the sign-in page. `TokensView.tsx` is the view of the API tokens of the user, where a new token shows its text one time.

The UI text follows the section "No AI slop".
